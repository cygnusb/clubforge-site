Betrieb: euer Server in einem Abend

Ein kleiner Server, drei Namen im DNS, ein Befehl: mit Vereinsname, Logo und Farben, am Ende mit erster Admin-Person. Das Zertifikat kommt automatisch von Let's Encrypt, Backups sind verschlüsselt, Sicherheitsupdates laufen von allein.

Die Anleitung liegt im Quellcode (folgt mit dem Pilot) Zurück zur Übersicht 
# frischer Server, Debian 12/13 oder Ubuntu 24.04
curl -fsSLO https://cygnusb.github.io/clubforge-site/install.sh
curl -fsSL https://cygnusb.github.io/clubforge-site/install.sh.sha256
sha256sum install.sh   # beide Prüfsummen vergleichen
sudo bash install.sh \
  --app app.mein-verein.example \
  --sync sync.mein-verein.example \
  --login login.mein-verein.example \
  --email vorstand@mein-verein.example \
  --club "Mein Verein" --version 0.2.0 \
  --logo https://mein-verein.example/logo-weiss.svg \
  --primary '#117733' --dark '#0a2a14' \
  --admin-first Vera --admin-last Vorstand

Der Ablauf

Fünf Schritte. Der Server zieht ein fertiges Image und baut nichts; der erste Start (Zertifikat, Anmeldedienst) dauert einige Minuten.

  1. 1Server mieten4 GB Arbeitsspeicher, EU-Standort. Bei Hetzner ab etwa 5 € im Monat.
  2. 2Drei Namen setzenapp., sync. und login. eurer Domain zeigen auf die IP des Servers.
  3. 3InstallierenInstaller per SSH, cloud-init oder eine OpenTofu-Vorlage für Hetzner, AWS oder Google Cloud.
  4. 4Erste Person anlegenadmin.sh legt Mitglied und Anmeldung an, das Einmalpasswort wird beim ersten Login geändert.
  5. 5Backup-Schlüssel sichernIn den Passwortmanager des Vereins, für zwei Personen. Ohne ihn sind Backups nicht lesbar.

Was ihr braucht

Einen Server

Linux (Debian 12/13 oder Ubuntu 24.04), x86_64 oder arm64, mindestens 2 vCPU und 4 GB RAM, 40 GB Platte, feste IPv4-Adresse.

Eine Domain

Drei Einträge setzen können. Die Namen sind frei wählbar, aber nach der Installation fest.

Offene Ports

22 (SSH), 80 und 443. Port 80 braucht Let's Encrypt zur Prüfung des Zertifikats.

Mail optional

Ein SMTP-Zugang für E-Mail-Benachrichtigungen. Ohne ihn funktionieren App und Push trotzdem.

Speicher für Kopien optional

S3-kompatibler Objektspeicher (Hetzner, AWS, Google) für Backup-Kopien außerhalb des Servers.

Speicher für Anhänge optional

Ein eigener S3-Bucket für Fotos, Dateien und GPX-Strecken, z. B. Hetzner Object Storage. Ohne ihn läuft alles, nur ohne Anhänge. PDF-Vorschauen rendert ein abgeschotteter Dienst ohne Netz auf eurem Server.

Platz für Karten optional

Die Kartenkacheln eurer Region liegen auf dem Server: Baden-Württemberg etwa 1 GB, ganz Deutschland etwa 7,4 GB. Ein Befehl lädt sie, Updates lassen sie in Ruhe; ohne sie zeigt die App Strecken als Linie.

Mitgliederliste optional

Ein API-Schlüssel für easyVerein oder eine CSV-Datei. Ohne sie legt ihr Mitglieder von Hand an.

Einen Passwortmanager

Für Backup-Schlüssel und die .env, mit Zugriff für zwei Personen.

Was es kostet

Richtwerte, Stand Herbst 2026. Preise vor der Bestellung beim Anbieter prüfen.

Hetzner Cloud

CAX11 oder CX22: etwa 4 bis 6 € im Monat. Hauptweg. Der kleine ARM-Server (CAX11) und der Intel-Server (CX22) laufen in Falkenstein, Nürnberg und Helsinki. Cloud-Server mit AMD-Prozessor gibt es zusätzlich in Ashburn (Virginia), Hillsboro (Oregon) und Singapur. Object Storage nur in Deutschland und Finnland. Für Vereine in der EU bleiben die europäischen Standorte die Empfehlung.

AWS

EC2 t4g.medium mit Elastic IP: etwa 25 bis 35 € im Monat, Region Frankfurt.

Google Cloud

e2-medium mit statischer IP: etwa 25 bis 35 € im Monat, Region Frankfurt.

Sonstiges

Domain etwa 10 bis 15 € im Jahr. Zertifikat und Software kosten nichts.

Erprobt

Auf echter Hardware getestet, nicht nur beschrieben.

Hetzner CAX11, 14.10.2026

2 vCPU arm64, 4 GB RAM, Ubuntu 24.04, Falkenstein, mit der OpenTofu-Vorlage und dem Image 0.1.1 von Docker Hub. Von tofu apply bis zum grünen Check etwa 2,5 Minuten, echte Let's-Encrypt-Zertifikate für alle drei Namen, keine Handgriffe auf dem Server.

Backup und Restore-Test

Verschlüsseltes Backup unter 1 MB für einen frischen Verein; der Restore-Test in einem Wegwerf-Container bestanden.

Im Betrieb

Etwa 1,3 von 3,8 GB Arbeitsspeicher und 16 % von 40 GB Platte belegt.

Eigenes Design

Getestet mit einem fiktiven Verein: Name, Logos per Adresse, Farben und eigener Begriff für Gruppen kamen beim Installieren mit; Web-App und Anmeldeseite folgten dem Verein, die erste Admin-Person war sofort da.

Und danach?

Backups

Täglich, verschlüsselt, 30 Tage aufbewahrt, auf Wunsch zusätzlich im Objektspeicher. Mit einem Befehl lässt sich ein Restore testen.

Updates

Sicherheitsupdates des Systems automatisch. Neue clubforge-Versionen mit update.sh: Backup, neues Image ziehen, Migration, Prüfung, Rückweg. Auf Wunsch kündigt es die Wartung vorher in der App an; Einstellungen und Kartenkacheln bleiben.

Überwachung

check.sh prüft DNS, Zertifikat, alle Endpunkte und das letzte Backup. Dazu ein externer Check und ein Backup-Herzschlag.

Datenschutz

Auftragsverarbeitung mit dem Hoster, Serverstandort in der EU, verschlüsselte Backups. Löschanfragen und Datenexporte kommen über die App, Fristen setzt der Server selbst um. Die Anleitung liefert die Checkliste.

Im Verein einstellen

Funktionen, Begriffe, Logo und Farben, Verhaltensregeln und Infoseiten pflegen Admins in der Verwaltung der App, ohne den Server anzufassen.

Welche App passt zu welchem Server?

Jeder Verein aktualisiert seinen Server zu eigener Zeit, die App ist eine für alle. Damit das zusammenpasst, gelten feste Regeln.

Server-VersionWeb-AppVerlangt mindestens App
0.2.00.2.0, kommt vom eigenen Server0.1.0
0.1.0, 0.1.1dieselbe Version, kommt vom eigenen Server0.1.0
  • Die Web-App liefert der Server selbst aus. Sie hat immer seine Version und passt deshalb immer.
  • Die Apps aus den Stores (sobald es sie gibt) unterstützen ab Version 1.0 Server der eigenen und der vorigen Hauptversion: App 2.x spricht mit Servern 1.x und 2.x.
  • Mindestversion: Jeder Server nennt die älteste App, mit der er noch arbeitet. Ist eine App älter, zeigt sie „Bitte App aktualisieren“, statt falsch zu arbeiten. Die Mindestversion steigt nur, wenn es wirklich nötig ist, nicht mit jedem Update.
  • Vor 1.0 können sich zwischen kleinen Versionen (0.1 → 0.2) noch Dinge ändern. Hinweise dazu stehen bei jeder Version unter Versionen und in der Update-Anleitung.

So hängt es zusammen

Lesen geht immer aus der lokalen Datenbank auf dem Gerät. Änderungen laufen als Commands zum Server, und der Sync verteilt das Ergebnis wieder an alle Geräte. Alle Dienste laufen auf dem Server des Vereins, aus einem gemeinsamen Image für alle Vereine; eigene Werkzeuge binden sich von außen über Dienstkonten und Webhooks an.
